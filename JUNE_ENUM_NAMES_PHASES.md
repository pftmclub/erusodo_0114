# June enum names: replace raw ids with enum members (refactor)

Plan key `june-enum-names` · branch `main` · kickoffs `kickoffs/june-enum-names/` · flag `SERV_IRUHADEV_JUNE_ENUM_NAMES` (one flag, family-wide) · log tag none (compile-time only, no behaviour change) · written 2026-10-26 by the user's request ("hardcoded integers that are enums") and a read-only survey; approved plan text lives in the session plan `jolly-churning-melody.md`.

## Context

June-port code carries raw integers that are enum values. The example that started this (`X2Lib/X2GuEve.cpp`, `JuneEveAccelCoreParticleName`):

```
case 200: case 0x56c4: case 0x56cf:  return L"BuffAttackCore";   ... if( 0x765d <= iSkillID_ && iSkillID_ <= 0x765f ) ...
```

- `200`..`206` are **already named** C++ members (`CX2SkillTree::SI_SA_COMMON_AURA_*_ACCEL`, `X2SkillTree.h:108+`), typed as numbers.
- `0x56c4` = 22212 = `RNSI_A_ABM_AURA_POWER_ACCEL`: in the live `Enum.lua` (`SKILL_ID`, l.12713), **not** in the C++ enum.
- `0x56cf` = 22223 = `RNSI_A_ABM_AURA_POWER_ACCEL_UPGRADE`: in June's Enum only.
- No rule says "name the id" and no tool finds raw ids. The survey (below) counted about 410 in June code.

**The registration rule (user, 2026-10-26):** register the name in the C++ enum, behind a flag, with June's value and June's name, and in `Enum.lua` where it is missing. **A value that is not registered in Enum.lua is not an enum value**, but investigate thoroughly before calling it stray (N1).

Three classes of finding drive the phases:

| Class | Meaning | Action |
|---|---|---|
| **A** | name already a C++ member | rename the literal |

## Rules

- **Authority for "is it an enum value":** June's `june_src_fixed/data036_kom/Enum.src.lua`, then the live `kom_contents/data036_kom/Enum.lua`. Never `ScriptData/*.xlsx`, never a guess, never a name invented to fit.
- **One flag, `SERV_IRUHADEV_JUNE_ENUM_NAMES`**, defined in `KTDXLIB/Always.h` (the first phase that needs it defines it, with the house comment block). Every changed site is `#ifdef` name / `#else` literal / `#endif SERV_IRUHADEV_JUNE_ENUM_NAMES`, generated by script as a `bytepatch.py` spec; these files are CP949. A header member that is defined but not used is harmless.
- **Registration shape:** members appended inside the existing enum body under the flag, **explicit `= value`, June's name**, as `SERV_IRUHADEV_JUNE_BUFF_ENUM` (`X2BuffFactor.h:107-151`) and `RANOX_PORT` / `ELYSION_PORT` (`X2UnitManager.h:2560-2900`) do. `CX2SkillTree::SKILL_ID`'s first June block goes just before the closing `};` at about `X2SkillTree.h:1554` (21000-33000 is free). Never renumber or rename an existing member; when March's name and June's share a value (`CONQUEROR` / `CONQUERER`, 9009) use March's.
- **Only what a site needs** is registered: not June's 1,857 skill / 1,298 NPC / 932 BTI / 1,173 BFI names.
- **Enum.lua** is a core-list file (BOM + CRLF, byte-exact). A line is added only for a name that June's data Lua indexes and the live table lacks, through `luasrc.py` (skill `x2-lua`); `core --check` and `ledger --check` stay PASS. C++-only names do not need an Enum.lua line.
- **Behaviour must not change.** Proof is mechanical: a throw-away probe asserts every new member equals the literal it replaces (N2), `flagcheck` proves flag-off = base.
- **Comments:** one short line (CLAUDE.md, 2026-10-20). Remaining file-local constants live in a named `_CONST_<CLASS>_JUNE_<phase>_` namespace plus `using` (CLAUDE.md, 2026-10-26); never `namespace { }`.
- **Scope rule** (`JUNE_PORT_BACKLOG_ORDER.md`, "Standing rules", *Scope*): a literal outside the listed files, or a studio (non-June) literal, is identified in the Done note and given its own bullet, not chased.
- **CP949 files** (`X2GuEve.*`, `X2GUUser.*`, `X2GUArme_VioletMage.*`, `X2SkillTree.*`, ...): `bytepatch.py` only, `file` + `git diff --stat` after.
- **`char-eve` is paused (user, 2026-10-26) until this plan closes**, so N3 has `X2GuEve.cpp` to itself. If char-eve resumes before N3 is done, N3 runs between two of its phases, never beside one. Resumed Eve phases (CH1l2 onward) then name ids from the first line, under the NZ rule.
