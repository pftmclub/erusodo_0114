# ProjectX2 (Elsword) - EU_CN_US trunk

Source for the Elsword DirectX 9 client, its five servers and the content tools,
used here to build and run the **offline client**. Start with [CLAUDE.md](CLAUDE.md)
(architecture, build recipe, rules) and [STATUS.md](STATUS.md) (current phases).

## What is tracked

Everything is tracked **except** what `.gitignore` lists. It is a blocklist, so a
new top-level directory is tracked by default. Not tracked:

| Not in the repo | Why | How to get it back |
|---|---|---|
| `Libs/` | Vendored third-party libraries (~60k files, 4+ GB) | See *Libraries* below |
| Build output (`Release_*`, `US_SERVICE`, `*.obj`, `*.pch`, `*.pdb`, `*.tlog`, `*.map`, ...) | Regenerated by the build | `python tools/build.py` |
| IDE caches (`*.sdf`, `*.ncb`, `*.suo`, `ipch/`, `.vs/`) | Regenerated by Visual Studio | Open the solution |
| Prebuilt binaries (`*.lib`, `*.dll`, `*.exe`, `*.zip`) | Not source | See *Libraries*; `elstools/elstools.exe` is the one exception |
| `march2014/` assets (`.ogg .x .tga .dds .avi ...`) | ~380 MB, re-derivable from the June 2017 client | Only the `.lua` and `_manifest.json` are tracked |
| `june_src_fixed/` | Decompiled June Lua, regenerable | `june2017_re/ljd_jun2017.py` over the June kom archives |
| `tmp/`, `.build/`, `DB_Backup/` | Scratch, build logs, local database dumps | - |
| `.mcp.json`, `elstools/elstools_config.json` | Hold absolute paths of one machine | Recreate locally |

The game data directory (the `.kom` archives, `els_db.sql` save file) lives
outside this tree. See CLAUDE_REFERENCE.md, "Deploying the offline client".

## Libraries needed (not in the repo)

Put these under `Libs/` at the tree root (project files reference them as
`$(SolutionDir)Libs\...`). Pass `SolutionDir` with a trailing slash when calling
msbuild; `tools/build.py` does this.

**Client (VS2010, `US_SERVICE`)**

| Library | Version / path | Used by |
|---|---|---|
| Boost | 1.44.0, `Libs/ExternalLib/Boost/boost_1_44_0` | client, `X2ServerProtocol`, servers |
| DirectX SDK | `Libs/ExternalLib/DXSDK` (`Include`, `Lib/x86`) | client, engine |
| FreeType | 2.4.11, `Libs/ExternalLib/freetype-2.4.11` | client, engine |
| SQLite | amalgamation, `Libs/ExternalLib/sqlite3` (`sqlite3.c`, `sqlite3.h`) | offline mode, `X2CashShopTool` |

**Servers (VS2003, not buildable on the current machine)**

| Library | Path |
|---|---|
| Intel TBB 2.2 | `Libs/ExternalLib/IntelTBB/tbb22_013oss` |
| BCL | `Libs/ExternalLib/BCL` |
| Boost 1.44.0, DirectX SDK | as above |

Other directories in the original `Libs/` (Log4cxx + APR, Lua 5.1.4, cppunit 1.12.1,
jsoncpp 0.5.0, KOGPatcher, `Libs/InternalLib/*`) are referenced by no current project
file; they are only needed if you open the legacy tool projects.

**Prebuilt binaries inside the tree that the build links but git ignores**

These come from the original studio checkout. If they are missing, copy them from it.

- `KNCSDK/lib_2010/*.lib` (Knc Debug / Lua / Security / Serializer, MD/ML/MT, release and debug); `KNCSDK/lib/*.lib` for VS2003. Headers and sources under `KNCSDK/` *are* tracked.
- `KTDXLIB/`: `CrashRpt.lib`, `CxImage.lib`, `cximageD.lib`, `jpeg*.lib`, `png*.lib`, `zlib*.lib`, `libxml-md.lib`, `libxml_mt.lib`, `unicows.lib`, `vld*.lib`, `winhoard.lib`, `KncFirewall.lib`, `Profiler*.lib`. (`luaLib.lib` and `luajitLib.lib` are built from `luaLib/` and `luajitLib/`.)
- `X2/`: `BugTrap.lib`, `BugTrapU.lib`, `MachineIdLib.lib`.
- `X2Lib/`: `HShield.lib`, `HSUpChk.lib`, `HsUserUtil*.lib`, `IGALib*.lib`, `MailMIME.lib`, `MailSMTP.lib`, `NPGameLib*.lib`, `NexonModuleD.lib`. (`X2ServerProtocol.lib` is built from `X2ServerProtocol/`.)

## Building

```sh
python tools/build.py --deploy      # builds luajitLib, luaLib, X2ServerProtocol, KTDXLIB, X2Lib, X2 and deploys
```

Toolchain: Visual Studio 2010 (`v100`) for the client. Details and the manual
msbuild recipe are in CLAUDE_REFERENCE.md, "Toolchains".
