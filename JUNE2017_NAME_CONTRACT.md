# June2017 effect data: name contract (Phase 10b, audit 2)

Generated by `june2017_re/names.py`; every row is also in `june2017_re/name_contract.tsv`.
Plan: `JUNE2017_EFFECT_REBUILD_PLAN.md`, Phase 10b. **Nothing was fixed.** This is the adoption
punch list: every effect name March's C++ asks for by literal, checked against what June's files
define.

## Method

- 432 translation units (every `.cpp` X2Lib and KTDXLIB build under `US_SERVICE`) preprocessed with
  `cl /P` under each project's own `US_SERVICE` flags: `#ifdef`'d-out calls do not count,
  stringized names do. 0 failed to preprocess.
- 48591 distinct string literals, wide and narrow (value, file, line), from X2Lib/KTDXLIB sources.
  Narrow counts: `CreateInstance_LUA` takes a `char*` name.
- Every row that is not *kept* is also checked against June's own binary (`unpacked_x2.exe` plain
  strings plus `xorstrings.tsv`): *gone* means June changed that call site, so March's must change
  on adoption; *still asked for* means June's code asks for a name June's data lacks: dead in June too.
- The loaded files: every `OpenScriptFile` / `Reset*Particle` / `Reset*XMeshPlayer` call in X2Lib
  and KTDXLIB opens only the standard `*Particle*.txt` / `*XMeshPlayer*.txt` set. The
  `data121` `rena_A_trapingArrow_Particle.txt` / `_Xmesh.txt` pair ships in both builds but is
  opened by neither: no loader names it in March's source or in June's binary.
- A literal is an **effect name** when March's own loaded data defines it: an effect set,
  a damage effect, or a templet in one of the eight particle / mesh-player systems. Case-sensitive,
  as the engine's `std::map<std::wstring>` lookups are. No API list is needed, so no call shape
  is missed.
- June side: the same namespaces, from June's 14 effect lua files (executed, route (b)) and every
  particle / mesh-player file June's loader opens.
