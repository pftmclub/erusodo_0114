## The problem

1. **Relative-level monsters.**
   - **Emulator today:** for a relative-level dungeon it uses `m_MaxLevel` (else `m_MinLevel`) as the monsters' base level
     (`X2Lib/Offline/Handlers_Room.cpp:1817-1836`, applied at `:1971` / `:1973`).
   - **Real server** (`KncWX2Server/CenterServer/DungeonRoom.cpp:3656-3710`): it starts from the party's average level at dungeon
     start (`GetAverageUserLevelAtDungeonStart`, under `SERV_DUNGEON_NPC_LEVEL`).
     - `DT_SECRET` clamps that level into [`GetDungeonMinLevel`, `GetDungeonMaxLevel`].
     - `DM_SECRET_HELL` mode then adds +5, or +5 + `GetSecretDungeonExtraStageNpcLevel()` on an extra stage.
     - Defence dungeons clamp to the minimum only.
   - **Why it matters now:** since C3z-3 the Secret Hells are 70-99, so the emulator spawns level-99+ monsters for a level-72 player.
2. **Server-only DungeonData keys that no client reads:**
   - `m_bSwitchingWithEventInfo` (read by `XSLDungeonManager.cpp:189`), `m_bForbidEnterDungeon`, `requireLevel`;
   - `m_fPoisonTimeLimit` / `m_fExtraStagePoisonTimeLimit`, `m_bArcadeMode`;
   - the server half of `DUNGEON_CHECK_CONDITION` (`DCC_NOT_DECREASE_SPIRIT`, `DCC_ONLY_GET_EL_EXP`, `DCC_EVENT_DUNGEON`, ...).

3. Gate:

   - every server-only key has a verdict.
