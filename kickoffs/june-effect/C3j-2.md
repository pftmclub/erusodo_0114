## Why this phase exists

The user confirmed (2026-10-10) that monsters fly up from Elsword's dash X in the June game. Ported as read, June's code kills that launch:
- InitState `327989e0 @327992a2-327992fd` falls back to UP = `m_UpDamage` (`+0x870c = +0x8690`).
- The NPC RT_UP case (`32769b72-32769bb3`) writes `nowSpeed.y` (`+0x308`) and queues `+0x8690` through `327590c0`.
- CommonStateStart `@327af3aa -> 3275a070` then copies `+0x40f0 / +0x40f4` into `+0x304 / +0x308` with no condition when nowState == `+0x870c`.

March's play-test proved the copy runs: 5 logged lines of `(-1110, 1950) -> (0, 0)`. **"Follow June" means "play like June", so a piece is missing or misread.**
That is a port gap, not a June bug (JUNE_BUGS 154 is provisional). Until it is found, `SERV_IRUHADEV_JUNE_FIX_BOUNDING_UP_SPEED` (ON) skips the copy.
