## The problem

June's client loader `AddDungeonData_LUA` (`unpacked_x2.exe 327e0f80`) reads 54 keys. March's loader reads none of the following.

In shared rows today:
- `MinAdequateMemberCount`, `MaxAdequateMemberCount` and `FixMaximumDifficulty` (51 rows);
- `DUNGEON_CHECK_CONDITION` (14 event / defence rows; read by the plain-string `BeginTable` near decompile line 960);
- `m_SuitableLevelFixValue` (5);
- Henir's `m_HardMinLevel`, `m_HardMaxLevel`, `m_HardRequireItemLevel` and `m_fExtraValue`.

Only in June-only rows, which C3y makes live:
- `additionalTicket` (a plain string);
- `m_bShowNpcKillCount`, `m_bNoDarkBackGroundBy60S`, `m_iRequireCompleteQuestID` and `m_bAprilFoolsDungeon`.

Inventory: the census column `june_unread_june_client_reads` (per row), and `dungeon_registry_loader_keys.txt` (March's set).

## Task

**Scope: every key above.** Gate: each key has a ported reader with its consumers, or a written June no-system answer.

1. For each key, find June's field offset in `327e0f80` and every reader of that offset (Ghidra xrefs). Classify each:
   - bind-only: the March member and its consumer exist;
   - port: June's consumer is missing in March;
   - no-system: June's consumer needs a system March lacks. Record June's answer when the value is absent.
2. Port per family, one flag each, with the original code in `#else`. Cite June addresses.
   - `DUNGEON_CHECK_CONDITION` has a client half (e.g. `DCC_NOT_USE_QUICK_SLOT`, `DCC_NOT_SUMMON_RIDING_PET`) and a server half.
     The server half is C3z-6's.
