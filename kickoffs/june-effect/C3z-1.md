## The problem

The C3x play-test (user, 2026-10-10) says the map layouts still look wrong. C3x replaced the world scripts and line maps with June's
and added the assets March lacked. But `npc_mesh_census.py --worlds` skips any name March already has (`if ln in march: continue`).

`june2017_re/world_asset_collide.py june2017_re/c3x_adopted_names.txt` counts the shared names: 221 of the 1,062 that the 205 adopted
files use differ in bytes from June's (Battle Air Ship `s1_ground1.y` is 14 KB in March and 70 KB in June). June's line maps therefore
sit under March's old geometry. The standing rule says June's asset wins at the same filename: always replace.

## Task

**Scope: every dungeon (user, 2026-10-10: "make sure to check all dungeon").** The 221 come only from the 205 files C3x adopted.
This phase covers every world that any dungeon script in kom_contents uses: the 378 rows of `world_census.py`, their world scripts and
line maps, identical ones included. A world script that is byte-identical to June can still name a mesh whose bytes June changed.
Build the name list from `world_census.tsv`, not from `c3x_adopted_names.txt`.

1. **Close the list.** Make the census take same-name files whose June bytes differ, for example a `--replace` switch on
   `npc_mesh_census.py --worlds` that reuses `world_asset_collide.py`'s compare.
   - Close it over the replaced meshes: inflate MSZIP with `fxdata.xfile_text`, and take every texture or nested model whose June
     bytes differ or that March lacks.
   - June's decoder is strict: a name June cannot decode to its manifest size is refused, never guessed. List those names.
2. **Who else uses them.** For each replaced name, list the March-side users that are not June bytecode: village and field world
   scripts, and the March-only event worlds (Air Ship s6, Dragon Road 4).
   - June wins there too (`june-behaviour-wins-even-when-it-removes-features`). The list is the record of what visibly changes;
     put it in the Done note, not a question.
3. **Stage** with `kom.py stage-june <list>`; replaced files go to `kom_backup_stage_june`.
   - Check every target kom's dir against its live archive first (C3x found data101's dir missing 1,071 entries; never pack that one).
   - Pack, and ask before every copy.
4. **Gate, per dungeon:** write `june2017_re/dungeon_map_parity.tsv` with one row per dungeon script: the dungeon, its worlds, the
   world script / line map / asset counts, and how many still differ from June or are missing.
   - Every row must read 0 / 0, except rows whose cause is named: a June-undecodable file, the data101 dir, or a world June dropped.
   - `world_asset_collide.py` and `npc_mesh_census.py --worlds` over the full list both report 0.
