## The problem

The 2026-10-09 adoption put June's own bytecode in place for 3,518 NPC / dungeon scripts. C3x audited the bindings of the **world**
scripts only. A June script that calls a method March never registered raises `can't find '<name>' class variable` (lua_tinker), so
the function aborts at that line, every time. C3z-1 found it on the gates: `IsVotingLuto` kept 10 gate scripts invincible (46 dungeons).

`june2017_re/c3z1_unbound_reach.tsv` lists **38** methods called by scripts that a registered dungeon reaches: its monsters' unit
scripts (C3z-2's census), its world scripts and the dungeon script. `IsVotingLuto` is done. These **37** remain. The top ones are
`SetMovieDescriptionData` (22 scripts / 59 dungeons), `GetStoredGUUser` / `SetStoredGUUser`, `InitStateCoolTime`, `GetHostGameUnit`,
`GetDyingStart`, `GetNowStateID_LUA` and `GetIsLastStage`. Their symptoms differ: stuck boss AI, summons that never fire, stage checks
that never pass.

## Task

1. **Re-run the census** (the C3z-1 Done note names its inputs). Cross-check it against the live ErrorLog: every `can't find '...'`
   name must be in the TSV. Add `.lua` methods called with `.` as well as `:` (`slot0.X(`), and the `g_p*` globals' methods.
2. **Triage each method** into one row of a new `june2017_re/c3z4_bind_plan.tsv`:
   - **bind only:** March already has the C++ method (`GetHostGameUnit` in X2Game.h, `GetDyingStart` in X2GameUnit.h). Find June's
     binder row (`june2017_re/xorstrings.tsv` -> `use_va`, then the pushed function in `31d95080`), check that June's body equals
     March's, and bind it.
   - **port:** June-only. Read the body (`disasm_range.py`; vcall thunks resolve through the vtables in `funcmap.tsv`) and port it
     with its members. Cite every address.
   - **system:** the method belongs to a June system March lacks (raids `GetNewBossRaid`, the tutorial guide manager, Ruto voting).
     Port June's *answer when the system is absent*, as `IsVotingLuto` did (design-missing-june-pieces), or route the system to a
     STATUS row of its own.
3. **Order by reach**, using the `n_dungeons` column. Build, deploy, and hand off a play-test per family.
