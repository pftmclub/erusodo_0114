## Task

Do "Phase X1": a read-only June kom reader in `tools/junekom.py`, stdlib only, with `list` / `extract` / `verify`. Add a line to
`tools/README.md`. X0 settled every container rule. The decode table is in X0's Done note. These points are easy to get wrong:

- **The two key-C seed loops differ.**
  - Algo 2 with seed index 0 (V.0.3) uses the plain step `crc=(crc>>8)^T[b^k^crc_lo]`, the same as March's
    `CalculateWithoutEncrypt`.
  - Algo 3 uses the NOT form, `ck=~b^k^crc_lo; crc=(crc>>8)^((T[ck]&0xffffff00)|ck)`.
  - Using the algo-3 form for algo 2 decodes nothing.
- **The Blowfish tail stays plaintext.** June decrypts only `len & ~7` bytes, because `31d26270` throws on `len % 8`. The 1-7 tail
  bytes are already zlib bytes. That is the elstools truncation.
- **Dispatch is by algorithm, not by version.**
  - Algo 0 is plain zlib.
  - Algo 3 is always key C + trailer + offset 4, even in V.0.4, where every entry still has a MappedID.
  - Algo 2 is Blowfish when the MappedID resolves (all V.0.4 entries do); otherwise it is key C with no trailer.
- **Blowfish uses the standard tables** (0 diffs from pi). You can regenerate P/S from pi or embed them. Do not read them from the
  June exe at run time.
- **Names.** The key-C seed lowercases each UTF-16 unit and appends its high byte when it is nonzero. ElementTree assumes the
  manifest is UTF-8. If any name is non-ASCII, check the manifest's real codepage before trusting a key-C failure on it.
- **Runtime.** X0's pure-Python Blowfish takes about 2 s for one 12 KB entry, including key setup. There are about 82k V.0.4 algo-2
  entries (GBs), so `verify` will take hours.
  - Cache one key schedule per index (300 at most).
  - Use `multiprocessing` across koms.
  - Run `verify` in the background, and add `--sample N` for quick checks.
- **Header checks.** Port all three:
  - manifest adler32 == header `0x40`, computed over the stored (encrypted) bytes;
  - count and FileTime sum (hex text) == header `0x34` / `0x3C`;
  - last offset == file size.
  
  Per-entry `Checksum` (= adler32 of the stored payload) is never read by June. Check it in `verify` anyway: it is free evidence.
