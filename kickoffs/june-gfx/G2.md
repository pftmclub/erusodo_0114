## Amended by G0 (2026-10-19)

Build from `june2017_re/g0_gfx_map.tsv` (rows targeted G2). What changed against the planning sweep:
- **`+0x108` means "GFx shown"** (ctor 1; render and the mouse swallow need `== 1`). **`+0x40` is Renderer2D, not the loader.**
  The Loader is embedded at `+8`.
- **Init order.** Init `31c456e0` runs from OnCreateDevice (`31be4510`, March `JuneOpenPerturbationMap`, X2.cpp:1323). The first
  DXUT reset then runs `31c43e60`, which calls InitHAL.
- **Input.**
  - June's PeekMessage loop calls `31c43ab0`. In March that loop is DXUT's (`DXUT.cpp:3962` / `4025`): hook it there.
  - MsgProc order: mouse `31c44040` first. It swallows only when it returns 1, `+0x108 == 1` and dialog-manager `+0x110 == 0`.
    `+0x110` is a June-only modal flag that March never sets: read a labelled stand-in false.
  - Then the stage chain, then keys `31c43890`. Keys run **even when a stage took the message**.
  - `+0x11c` (mouse on) is written only at `32577e9c`: find March's point for it.
- **`+0x84` = the current CX2State.** CKTDXApp `31be2fd0` / `31be3000`, around the state change. The stage then gets vslot
  `0x2c( movie wrapper )`, which is June-only. AS "MSG"( n ) and the IME / Enter / arrow forwards reach that stage's MsgProc with
  0x467 / 0x46c / 0x46d.
- **Opener.** Kom member first. On a miss, use the SDK default `FileOpener::OpenFile` (disk, URL as given): that is how the loose
  scene `.swf` load. Map it onto `KGCMassFileManager` (kom) plus the SDK fallback, not onto March's loose-first `LoadDataFile`.
- **Fonts.** The SDK has no FxPlayer FontConfigParser. Transcribe June's (`31c43d00`, `31d22280`, `31d227e0`, `31c44ff0` with
  the fontlib-exists fallback, `31d21e10` apply). `fontconfig.font` is UTF-16 with one `[FontConfig "US"]` section,
  `fontlib "fonts_Tahoma.swf"`, one `map` and 9,133 `tr` lines.
- **Sound.** FMOD SoundRenderer on `(app+0x200)+0x40`, Audio state (`31c43700`, `+0x110`).
- **IME.** Skip, with one log line: no SDK source, and no `ime.xml` / `IME.swf` in June's data.
- **4.0.15 vs 4.2.22.** June's Movie / MovieDef vslot numbers and state ids are 4.0.15's. Call the 4.2.22 API by name
  (`SetViewScaleMode( SM_ExactFit )`, `SetViewAlignment( Align_TopLeft )`, `Advance( dt, 2 )`, `HandleEvent( SetFocus )`, ...).
- **Resize.** March has no resize hook (`31be2a00`): feed the present params at reset and label it a stand-in.
- **Open rows** (`+0x18` block, `+0x8c` map, `+0xd8`, `+0x118`): name them while transcribing.

## Amended by G1 (2026-10-19)

- G1 is in: `Scaleform::GFx::System` is up in the CKTDXApp ctor (`KTDXLIB/KTDGFXRuntime.cpp`, `KTDGFXRuntime_Init`); the manager is built after it and deleted before `KTDGFXRuntime_Shutdown()` in the dtor.
- Linked: `libgfx`, `libgfx_as2`, `libgfx_as3`, `libgfxrender_d3d9`, `pcre`. The client's zlib 1.2.3 / libpng 1.2.24 / jpeg are the one copy; libgfx's missing
  `deflate*` / `inflate*` / `png_longjmp` / `png_set_longjmp_fn` are shimmed in `KTDGFXRuntime.cpp`. **A GFx PNG file load fails cleanly** (libpng 1.2.24 rejects "1.5.13"); `.gfx` / `.swf`
  do not use it. If a GFx file needs an external PNG, say so; the fix is a renamed private libpng, not a change to the shims.
- No `Sound::` symbols were unresolved at G1. The FMOD renderer sources (`Src/Sound`) are still G2's to compile in (per-file include dirs in `KTDXLIB_2010.vcxproj`, as for `KTDGFXRuntime.cpp`).
- New `.cpp` files under the flag start with `#include "StdAfx.h"` outside it (PCH); flagcheck reports that line as the one FAIL.
