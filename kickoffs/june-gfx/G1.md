## Amended by G0 (2026-10-19)

G0 settled item 1 (`june2017_re/g0_gfx_map.tsv`, rows `31c451d0`, `33193b90`, `31c43700`):
- **Both AS libs.** June registers AS2Support (state 0x21) and AS3Support (0x22, `33193b90` registers the SymbolClass / DoAbc tag
  loaders). The root movie is AS3 (`main.gfx` carries `gfxAS3.*` packages). Link `libgfx`, `libgfx_as2`, `libgfx_as3`,
  `libgfxrender_d3d9`, and `pcre` (AS3 RegExp). Add `libgfxexpat` / `expat` only if the link asks: June sets no XML state.
- **zlib is needed.** June sets ZlibSupport (0x19) and 500 of the 501 CFX files are zlib. It also registers 4 image-file handlers
  (state 0xb). Keep one jpeg / png / zlib copy on `LNK2005`, as the section says.
- **Sound.** June does set an Audio state (0x1c): an FMOD SoundRenderer on KTDS's own `FMOD::System`. The SDK ships it as source
  only (`Src/Sound/Sound_Sound.cpp`, `Sound_SoundRenderer.cpp`, `Sound_SoundRendererFMOD.cpp`; `GFxConfig.h:273` enables
  `GFX_SOUND_FMOD` for MSVC). If `libgfx` leaves `Sound::` symbols unresolved, compile those three files into KTDXLIB under the
  flag against March's FMOD Ex headers (per-file include dirs) and say so. G2 creates the renderer.
- **No IME lib.** It is not in the SDK, and June's `ime.xml` / `IME.swf` are absent from its own data. G2 skips it.
