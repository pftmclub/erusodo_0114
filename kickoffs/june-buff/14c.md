## Task

1. **RE (Ghidra, June `unpacked_x2.exe`).**
   - **Readers.** Re-run the reader sweep: every `byte ptr [reg+0x16a]` compare or move whose preceding 24 bytes load `g_pMain` (`0x3377585c`). The 14b session found 68. Also check for `this`-relative reads inside CX2Main methods, since those have no `g_pMain` load in front.
   - **Writers.** The setter `31d716c0` has about 19 callers, most in `324c..3251`. The ctor zeroes the byte at `@31e4967f`. Find any other `mov byte ptr [esi+0x16a]` writers on a CX2Main `this`.
   - **Name it.** Use the setter's callers, its `+0x16b` once-latch, its key-config call (`g_pMain+0x7ec` -> `31f5e290`) and any Lua binding or `xorstrings.tsv` key. The name tells you which June mode this is.
   - **Classify every reader and caller** as one of: engine code whose function March has; character code; or a June-only system.
   - **Record it.** One `funcmap.tsv` row per function. If there are many, put them in one `.tsv` and add a single funcmap row that links to it.
2. **Port** under the new flag, with March's code in `#else`:
   - the member, the setter and the ctor zero;
   - every engine reader whose function March has, including the 14b clamp at `X2GUUser.cpp`: June's test is `XS_TRAINING_GAME || +0x16a` (`@32049b37-32049b47`);
   - the setter's callers where March has the caller.
   Character-code readers go to `JUNE2017_CHARACTER_PORT_CHECKLIST.md` §7; the engine side is still ported (standing rule D8). Readers in June-only systems are listed, not ported.
3. **Reach.** Say whether anything March runs can set the flag.
   - If something can, write the play-test from that route, dev console first.
   - If nothing can, say so with the caller evidence. The ported readers then stay inert, which is June's behaviour without the mode. In that case the play-test is a regression check only: the training game still clamps HP, and a normal field death still happens.
4. **Stop and ask** if porting a caller would mean bringing in a whole June-only UI or game mode. That is a scope decision for the user.

**Done gate:** every reader and caller is classified with a funcmap entry; the range flagcheck passes; the play-test or the proven absence is recorded; there is a Done note under the plan's "Phase 14c" section; the 14c STATUS row is updated.
