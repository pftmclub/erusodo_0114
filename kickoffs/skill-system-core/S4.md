## S0a amendments (2026-10-17)

S0a re-read the override in the binary (`3263fe41-32640054`) and confirms funcmap rows 1302-1306 (Effect C1a). The spec:

1. **Site.** In `SetDamageDataFromLUA`, after `NUMERICAL_DATA_INDEX` / `NUMERICAL_DATA_NAME` are read and every other key is parsed,
   and before the table's closing `luaManager.EndTable()` (planning cited `:605`; it is now near `X2DamageManager.cpp:827`, so
   locate it by the code). June runs it after `ROSE_WEAPON_ATTACK_TYPE` and the `+0x604` key, and before `SetDamageExceptionProcess`
   (vslot 0x2b8). That function multiplies PHYSIC / MAGIC by `fPowerRate`, so the override is scaled by the power rate.
2. **Gate, in June's order. Any failure skips the whole block.**
   - `INDEX > 0`, or `NAME` not empty.
   - `APPLIED_SKILL_ID` (`+0x5c4`) or `DAMAGE_SKILL_ID` (`+0x5cc`) non-zero. `USED_SKILL_ID` is not a trigger.
   - `g_pData` and its skill tree (`+0x50`) are non-null.
   - The attacker `optr` (`+0xc`) is valid (`31e55680`).
   - The attacker's unit type `+0x264` is 0 (user: that unit) or 1 (NPC: `GetOwnerGameUnit 32759f00`). Any other type is skipped,
     and so is a null result.
3. **Skill and level.** `skill = APPLIED_SKILL_ID ? APPLIED_SKILL_ID : DAMAGE_SKILL_ID`.
   - `level = owner CX2Unit (+0x867c) -> UserSkillTree (+0x494) .GetSkillLevel( skill, 0, 0, 1 )` (`32890620`, capped at 30).
     June does no null test on `+0x867c`: keep that verbatim. If a March user unit can lack a `CX2Unit` (check the AI-party bots), add a `JUNE_BUGS.md` row.
   - `templet = GetEquippedActiveSkillTemplet( skill, 1 )` (`31fca8e0`; memo swap `328905b0`, slots A then B, else the acquired
     templet).
   - Skip unless `level > 0` and `templet` is non-null.
4. **Row.** `INDEX > 0 ? 320717e0( templet, INDEX, level ) : 32078060( templet, NAME, level )`.
   - By index: elements 1..n; out of range gives 4 x 0.0f.
   - By name: the first element whose `m_wstrName` matches (`wstring::compare`); none gives zeros.
   - Row clamp `320716c0`: `row = min( level - 1, count - 1 )`, unsigned, so level 0 also takes the last row. An empty element gives
     zeros.
   - Element layout (S2 builds it): `m_wstrName`, `m_ParamType` (default `L"i"`, unused), and 16-byte rows
     `{ value, pvp_rate, tech_point, hit_add_mp }`. `m_Pvp_Rate` defaults to 1.0, the other two to 0, and each side array is
     clamped to its last entry (`s0a_templet_keys.tsv`, `NUMERICAL_DATA%d` rows).
5. **Writes, in this order. Each is unconditional, so a zero row zeroes all five.**
   - `damageType (+0) != DT_MAGIC (1)` -> `PHYSIC (+0x38) = value * 0.01f` (the constant `0x334436a0` is the double of `0.01f`;
     multiply in x87 and store as float).
   - `damageType != DT_PHYSIC (0)` -> `MAGIC (+0x3c) = value * 0.01f`. `DT_MIX` and `WEAPON_*` write both.
   - `PVP_RATE (+0x538) = pvp_rate`.
   - `TECH_POINT (+0x34) = _ftol2( tech_point )`, which truncates.
   - `HIT_ADD_MP` (protected `+0x3f8`) = `hit_add_mp`, written only if it differs (`fucompp`; equal skips the protected setter).
6. **The three past-the-end blocks** (`c1a_numerical_blocks.tsv`, result "index out of range"). Each gets a `JUNE_BUGS.md` row and
   is kept verbatim: zero damage once the skill is learned.
   - `DamageEffect_ESK_Mortal_Blow_Ultimate_Fire_Ground`: 21006 Mortal Blow, INDEX 2.
   - `DamageEffect_LD_FLICK_SHOT_Projectile_Sub_Trans_Delayed_Expolsion`: 30003 Flick Shot, INDEX 5.
   - `DamageEffect_SA_EMK_WindBlade_Ultimate_Projectile`: 21013 Wind Blade, INDEX 2.
7. **Self-check sample.** Take it from `c1a_numerical_blocks.tsv` rows with `result = ok`. The L1 columns are level 1, so compare
   at level 1. The overriding values only exist once S3 has loaded June's templets, which is why S4 depends on S3.
8. **June-side power-rate note for `MODS.md`.** `GetSkillPowerRateValue 32071720` gives an upgraded skill (`m_DeleteSkillIDByUpgrade`
   non-zero) its power rate from SA `0xad` = `SA_ULTIMATE_STRENGTHENED_SKILL_POWERRATE` (S2 ports it). Damage logged for an
   "[Enhanced]" skill therefore carries that factor as well.
