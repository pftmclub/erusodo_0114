## S0b amendments (2026-10-17)

- **March's container is not June's.** `m_StateList` is `std::map<USHORT, UserUnitStateData>` (`X2GUUser.h:1117`),
  which is node based. A pointer to an entry survives every insert, and the only erase is the destructor's `clear()`
  (`X2GUUser.cpp:1552`). June's is a vector at `+0x7cec` (100 B entries), and its state id is `(ptr - base) / 100`.
  The "reference outlives a reallocation" risk therefore does not exist in March. Decide, and say which in the Done
  note: pointers into the map entries, or June's vector. Either way the state id must stay derivable.
- **Copy sites today** (the ledger's lines have moved): `X2GUUser.cpp:6697` (Future) and `:6761` (Now), plus the
  `:6762` `stateID` re-stamp. There are no other whole-struct writes. The only raw pointer is a local in `InitState`
  (`:5707`). The March map, read counts and per-file lists are in `june2017_re/s0b_march_state_ptr_map.md`.
- **Hazards that become real with pointers:**
  1. `m_NowStateData.m_fPowerRate *=` would compound into the shared entry on every re-entry. The sites are
     `X2GUUser.cpp:6778-6779`, Chung `:13134` / `:13376`, Elsword `:13201` / `:13206` and Lire `:19170`. Raven's three
     `=` writes are idempotent. Read where June keeps the running power rate (`3203c3a0 @3203c649` multiplies it)
     before converting.

     that rewrites the running state; the `31fd2af0` snapshot covers only the five delegates. Port whatever June
