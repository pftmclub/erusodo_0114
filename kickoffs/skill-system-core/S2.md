## S0a amendments (2026-10-17)

The map is `june2017_re/s0a_templet_keys.tsv`: 260 rows, one per key, with getter, default, June store offset, March equivalent and
June readers. Function-by-function: `june2017_re/s0a_skilltree_tu_map.tsv`. Port June's behaviour where it differs from March
(rule 1). These are the differences that change results.

1. **`AddSkillTemplet_LUA 32216320`, whole.**
   - **No padding.** June calls the array reader with fill = 0 for `m_SkillCoolTime`, `m_MPConsumption` and
     `m_RequireCharacterLevel` (`@3221672c-3221677e`). March's `SetSkillVlaue` pads them to 30 by repetition. The getters are the
     same in both builds (`320717b0` cool time, `32071780` MP: index past the end gives 0), so a 1-entry array gives 0 above level 1.
     June data has 1,382 one-entry cool-time arrays. Keep it; the S2 review checks which callers pass a level above 1.
   - `m_Stat`'s five arrays (`32207960`) do pad, as in March.
   - **An empty `SA_*` table inserts nothing** (`3220b740`). March inserts `{ 0.f }`.
   - **`IN_HOUSE_TEST_ONLY == true` drops the templet** (EndTable, return false). June is a service build; March's drop sits under
     `_SERVICE_` and is off here. June data sets it 0 times, so the effect is nil, but port June's form.
   - **Duplicate `m_eID`:** the insert fails, the templet is not added, and the function returns true.
   - **Power rate:** `32207430` copies the `m_ePowerRate` row of the skill tree's power-rate map (`+0x30`) into the templet's
     `+0x140` vector, but only when that row has exactly 30 entries (`0x78` bytes).
   - **New fields:**
     - `m_ExtraIconInfo%d` (n = 1, 2, ... while `BeginTable` succeeds) -> `vector< pair< m_wstrTextureName, m_wstrTexturePieceName > >`;
     - `m_DeleteSkillIDByUpgrade` (`+0x178`); when non-zero, also `skill tree +0x20 map[ value ] = m_eID`;
     - `NUMERICAL_DATA%d` (`+0x17c`; layout in the S4 amendments);
     - `SKILL_ABILITY_TYPE` 143-202: the 60 names in the tsv, appended after `SA_DP_USE_REL = 142` in June's order. June's values
       1-142 equal March's, including the studio's `SA_TEAM_ATK_MAGIC_REL` -> 13 quirk, which is kept.
   - `31c59710` (anti-tamper memory registration) is not ported.
2. **`AddSkillTreeTemplet_LUA 32210670`.**
   - Reads `m_eUnitClass`, `m_iSkillID`, `m_iMasterLevel`, `m_iRowIndex`, `m_iColumnIndex`. **It no longer reads `m_iPrecedingSkill`.**
   - A skill with no templet logs "skilltemplet is null on loading skilltree templet" and returns false.
   - The guild tree (`32210c70`) keeps `m_iPrecedingSkill`.
3. **`AddSealSkillInfo 3220a350`.** Takes `m_iItemIDList` (several unseal items, each a key into the seal map `+0x70`) where March
   takes the scalar `m_iItemID`. `m_eUnitClassType` and `m_SkillID` are as in March. `m_iSealSkillGroupID` is not read.
4. **`AddSkillPowerRate_LUA 32209d80` and `AddDefaultSkill_LUA 32209f70`** have the same shape as March's. June adds
   `SPRT_HYPER_CLASS = 5` (`SPRT_END = 6`) to `SKILL_POWER_RATE_TYPE`; the C++ enum needs it.
5. **`OpenScriptFilePostProcess` (Lua) is bound to a bare `RET` (`31f3f070`).** June does that work in `OpenScriptFile 322083e0`
   after the two loads: `CommandIconData.lua`, then `32207dd0`, `32206050`. That order is in the TU map. Port `32206050`'s pass
   into `OpenScriptFile` and keep the Lua binding a no-op. `GetMaxLimitedSkillLevel_LUA` returns 30 (`3208de60`).
6. **The upgrade map and swap.**
   - `32205c00( id )`: skill tree `+0x20` find; returns the upgraded skill, or -1.
   - `CX2UserSkillTree 328905b0( id )`: if the user's acquired map (`+0x4ac`, size `+0x4b0`) is empty, return `id`. Otherwise
     `up = 32205c00( id )`, and return `up` when `up > 0` and the user has learned `up`, else `id`.
   - So June resolves "learned / equipped" for an upgraded skill from the base id. A base id resolves to its "[Enhanced]"
     templet once that one is learned. It is used by `31fca8e0`, `32890720`, `31fcf3e0` and `3201ad10`.
   - `328905b0` is called inside `GetSkillLevel 32890620` (`@328906d7`) and `GetUserSkillTemplet 32890720` (`@3289073b`), and
     in about 40 other places. Every level and templet lookup by a base id therefore sees the "[Enhanced]" skill once it is learned.
   - **The three `_ULTIMATE` gates** use June's test "the equipped version is the upgraded one", in two forms:
     - `SPEED_TIME_ULTIMATE`: inline at `31fe3a60`, `31fca8e0( state skill, 1 ) +0x178 != 0`.
     - `BUFF_FACTOR_ID_ULTIMATE` and DamageEffect's `_ULTIMATE` keys: `31fcf3e0` (ParsingBuffFactorID `32630d20`, CEffect ctor
       `@31f7b81f`): swap `328905b0`, then `GetSkillTemplet( result ) +0x178 != 0`.
     - `32071e70( id )` (new, the same test as a function; callers `320462a0`, `327b1f30`, class code `32cefa2d`) is needed later
       by class ports. Port it with the gates.
7. **`GetSkillPowerRateValue 32071720`:** if `+0x178 != 0`, `32206fb0( 0xad, level, &out, 0 )`. `0xad` = 173 =
   `SA_ULTIMATE_STRENGTHENED_SKILL_POWERRATE`, a new SA value, so it needs item 1's enum. When that is found, return it; otherwise
   `+0x140[ level - 1 ]`, else 0.
8. **March-data gate.** March's file uses none of the new keys, so loading it through June's parser changes exactly the four points
   in item 1: no padding, empty SA tables, `IN_HOUSE_TEST_ONLY`, and the 30-entry power-rate copy.
   - Log the padding difference. The play-test's "unchanged behaviour" holds where March arrays already have 30 entries.
   - List the March templets with a short array that a level above 1 reaches (S2 decides from the log). If any exist, the
     March-data gate becomes "June's rule applied to March data", and the Done note says so.
9. **Bindings June adds on `CX2SkillTree`:** `IsMyClassSkillID_LUA 32205f40` (my class's tree has the skill),
   `GetMaxLimitedSkillLevel_LUA`, `AddSkillTypeColor 3220baf0` (S7) and `AddCommandIconData_LUA 3220f8d0` (S7).
10. **`GetSkillAbilityValue 32206e50` / `32206fb0` take numerical data first.**
    - Each one looks up the SA name `g_SkillAbilityName[ type ]` (static `wstring[203]` at `0x3379e6b0`, filled in the `CX2SkillTree`
      ctor `3221afb0`) among the templet's `NUMERICAL_DATA` elements (`3221e930`).
    - **Found:** `value * ( bPvp ? pvp_rate : 1.0 )` from the level's row (`320716c0`), with no x0.01.
    - **Not found:** the `+0x164` SA map, `vector[ level - 1 ]` (0 past the end).
    - June data has 1,056 blocks named after 91 SA types (`SA_EFFECTIVE_TIME` 124, `SA_DAMAGE_REL` 54, ...), so after S3 most
      ability values come from this path. S4's damage override is a different consumer.
    - The name table equals the SA enum names (slot 12 = `SA_TEAM_ATK_MAGIC_REL`, 87 = `SA_CHARGE_CANNONBALL`,
      113 = `HP_CONSUME_REL`). Port it with the enum (item 1).

      The dispatcher `32216150` (22 cases) has no case for them. This is a candidate: S7 confirms it and finds June's learn path (`CX2UISkillTreeNew2015`).
    - S2 keeps March's handlers unchanged.
    - Event ids: June = March + 9 for the skill block (`0x11f..0x12d`). S2 needs no packet change.
    - `CX2SkillTree` members (ctor `3221afb0`): `+0x10` class -> tree rows, `+0x20` upgrade map, `+0x30` power rate, `+0x40` default
      skills, `+0x50` / `+0x60` (the TU map's open point: a second class tree map that `32206050` clears), `+0x70` seal items.
    - `GetSkillTemplet` is `( id, level = 1 )` over templets stored by value. Port its semantics, not its storage.
    - The UserSkillTree's 5-slot changes (`GetSkillSlot`, `OnFrameMove`, gage index `i / i+5`, ...) are S5's (S0b's map), not S2's.
